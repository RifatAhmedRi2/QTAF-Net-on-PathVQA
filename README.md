# QTAF-Net: Question-Type-Aware Multimodal Fusion for Pathology VQA

**COMP 6001 — Computer Vision and Multimodal Machine Learning**  
**Capstone project** | PathVQA | PyTorch | Kaggle notebooks

This repository contains eight documented Jupyter notebooks for a comparative study of **pathology visual question answering (VQA)**. The project develops **QTAF-Net**, which combines a spatial CNN, a bidirectional LSTM question encoder, question-guided visual attention, a question-type predictor, and type-aware multimodal fusion. Its performance is compared with five baseline models and three QTAF-Net ablations.

The notebooks include dataset preparation, model training, validation-based checkpoint selection, fine-tuning, attention visualizations, and a shared **held-out test evaluation**. This is an experimental machine-learning project, **not a clinical diagnostic system**.

## 2. Dataset and preprocessing

**Dataset:** `flaviagiammarino/path-vqa`, downloaded through Hugging Face `datasets`.

| Split | Original question–answer examples |
| --- | ---: |
| Training | 19,654 |
| Validation | 6,259 |
| Held-out test | 6,719 |

An exact decoded-image SHA-256 comparison detected one image shared between training and validation. Its **six training question–answer records** were removed, leaving **19,648 training examples**. Validation and test sets are retained unchanged. This check does not rule out all near-duplicates or patient-level leakage.

Shared preprocessing and representation:

- Images are converted to **RGB**, resized while preserving aspect ratio, and centred on a white **224 × 224** canvas; tensors contain pixel values scaled to `[0, 1]`.
- Questions are lowercased and tokenized with `re.findall(r"\w+|[^\w\s]", text.lower().strip())`, then padded or truncated to **32 tokens**.
- The shared question vocabulary contains **3,972 tokens**, including `<PAD>` (index 0) and `<UNK>` (index 1).
- Yes/no answers use a **2-class** output; open-ended answers use the **1,000 most frequent training-answer strings**.
- Open-ended answers not included in the training answer vocabulary are excluded from the open-answer cross-entropy loss, but **count as incorrect for exact-match evaluation**. In the held-out test split, **1,128 of 3,357** open-ended reference answers are outside this fixed vocabulary.

**Important:** Notebooks 02–07 load `word2idx` and/or `open_answer2idx` from the original `late_fusion_latest.pth` generated by Notebook 01. This is done **only to reuse vocabulary mappings**, not to transfer pretrained model weights.

## 4. Training workflow

1. Open **Notebook 01** in Kaggle and run its setup, data-overlap checks, cleaning, preprocessing, and original 1,000-answer baseline training sections. Download **`late_fusion_latest.pth`** and **`best_late_fusion.pth`**. The `late_fusion_latest.pth` checkpoint carries the mapping dictionaries needed by the other notebooks.
2. Use Notebook 01's fine-tuning section to continue its **best original checkpoint** at a reduced learning rate. The separate 2,000-class experiment is optional and is **not** part of the nine-model final evaluation.
3. Attach the original **`late_fusion_latest.pth`** as a Kaggle Input for each of **Notebooks 02–07**. Run their data setup, architecture definition, original training, and fine-tuning sections. Download each model's **best fine-tuned checkpoint**.
4. Place all **nine** fine-tuned `.pth` files plus `late_fusion_latest.pth` in the private Kaggle Input dataset named **`pth_files`**.
5. Attach that dataset to **Notebook 08**, check its input directory, and run its cells from top to bottom. It loads checkpoints with strict state-dictionary matching and evaluates the untouched test split **without additional training**.

**Typical training protocol:** models start from random weights (no external pretrained model weights); original training uses Adam with learning rate `0.001`, weight decay `1e-5`, batch size `32`, up to `30` epochs and early-stopping patience `5`. Fine-tuning restarts from each model's best original checkpoint using a **fresh Adam optimizer**, learning rate `0.0001`, up to `10` additional epochs, and patience `3`. The notebooks use gradient clipping at `1.0` and seed `42`. **Validation**, not test accuracy, selects checkpoints.

If resuming a Kaggle session, follow each notebook's own *resume / restore* instructions rather than rerunning original training unnecessarily.

## 6. Model design and evaluation rules

**QTAF-Net architecture:** the spatial image encoder produces a **28 × 28 × 256** feature map (784 spatial positions with 256 channels). A trainable 128-dimensional word embedding and BiLSTM with 128 hidden units per direction produce a **256-dimensional question representation**. Question-guided attention aggregates visual evidence, and predicted question-type probabilities inform the fusion pathway. Two answer heads predict yes/no or one of 1,000 open-answer classes.

The three ablations test:

1. **No attention:** replace question-guided spatial attention with mean pooling.
2. **No type-aware fusion:** replace type-conditioned fusion with a shared fusion MLP while retaining the type predictor and two answer heads.
3. **Single head:** replace the two answer heads with one **1,002-class** classifier, using direct prediction rather than oracle head selection.

**Routing matters for comparisons:** the main evaluation uses **oracle answer-type routing** for dual-head models, including the image-only and question-only controls. Full QTAF-Net and its two dual-head ablations additionally report **predicted-type routing**. The single-head ablation uses **direct** classification. Oracle-routed metrics use ground-truth answer type and do **not** describe a fully independent deployed system.

**Metrics:** overall exact-match (EM), yes/no accuracy and class-wise/macro precision, recall and F1, open-ended EM, mean token F1, and smoothed sentence-level BLEU-1/BLEU-4. Answer matching relies on string normalization; it does not establish clinical or semantic equivalence.

## 7. Main held-out test results

The following figures come from `all_model_test_metrics.csv` and are rounded to two decimals. For dual-head models, the table shows **oracle** routing; the single-head row uses direct prediction.

| Model | Overall EM (%) | Yes/No accuracy (%) | Open EM (%) |
| --- | ---: | ---: | ---: |
| CNN + BiLSTM | **55.23** | 86.76 | 23.65 |

| SAN | 55.02 | **86.85** | 23.15 |
| QTAF without type-aware fusion | 54.84 | 86.59 | 23.06 |

Differences between the top three systems are small and should not be interpreted as established superiority from one split and one trained checkpoint per architecture.

## 9. Reproducibility and limitations

- All models were initialized without external pretrained model weights, including `resnet18(weights=None)` in Notebook 07.
- The data cleaning explicitly checks decoded RGB image equality between training and validation; it is **not** a comprehensive duplicate or patient-level audit.
- Results are tied to the specified PathVQA split, the fixed 1,000-answer label space, and the saved checkpoints. **33.60%** of the test open-answer references fall outside that label space.
- Random seeds help reproducibility but do not guarantee identical results across hardware or library versions.
- The nine models differ in architecture; parameter-matched, multi-seed and external-dataset comparisons are outside the scope of these notebooks.
- Statistical tests described in the accompanying research report use separate paired-prediction analysis artifacts; **Notebook 08 does not itself run McNemar or paired bootstrap tests**.
- These models and attention visualizations are research prototypes **not intended for clinical diagnosis**.
